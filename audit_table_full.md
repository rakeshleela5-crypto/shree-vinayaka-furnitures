# Forensic Code Audit Report: Shree Vinayaka Furnitures ERP & POS
**Role**: Principal Full-Stack Systems Architect & Forensic Code Auditor  
**Phase**: Phase 1 Only (Read-Only Audit — Zero Code Modifications Applied)  
**Target Codebase**: `frontend/src` (React 19 + Vite + TypeScript) & `backend/app` (FastAPI + PostgreSQL + SQLAlchemy)

---

### Executive Forensic Summary

A comprehensive, file-by-file forensic audit of the entire codebase was conducted to identify all client-side memory traps, unpersisted React state (`useState`), hardcoded mock arrays (`INITIAL_`, `DEFAULT_`, `MOCK_`), un-synced `localStorage` read/writes, and disconnected or missing FastAPI/PostgreSQL endpoints.

#### Key Forensic Metrics:
- **Total Frontend Files Scanned**: 84 components, views, utilities, and services across `frontend/src`.
- **Identified Isolated State & Persistence Gaps**: **87 critical architectural findings**.
- **Active `localStorage` Data Traps**: 29 business state keys (excluding auth tokens and theme toggles) storing enterprise business data in client browser storage rather than PostgreSQL.
- **Trapped Mock Arrays**: 64 static mock constants in `retailDaddyData.ts` and `retailDaddyStockData.ts` used to seed runtime component state.
- **Unpersisted Mutation Handlers**: 48 form save/add/update/delete handlers mutating local React state without awaiting transactional FastAPI `POST`, `PUT`, `PATCH`, or `DELETE` requests.
- **PostgreSQL Coverage Available**: Backend already possesses **82 SQLAlchemy tables** across 20 domain models, but numerous endpoints are either bypassed by client-side local caching or missing granular batch/status-transition capabilities.

### Payload Mismatches & API Contract Disconnects

Beyond client state traps, the forensic audit identified specific payload mismatches between frontend types in [retailDaddy.ts](file:///c:/Users/rakes/shree%20vinayaka%20furnitures/frontend/src/types/retailDaddy.ts) and backend SQLAlchemy models in [backend/app/models/](file:///c:/Users/rakes/shree%20vinayaka%20furnitures/backend/app/models):

1. **Held Carts**:
   - Frontend models held carts with full cart arrays in `localStorage('svf_held_carts')`.
   - Backend has table `held_carts` in [backend/app/models/sale.py](file:///c:/Users/rakes/shree%20vinayaka%20furnitures/backend/app/models/sale.py), but lacks active routes under `/api/v1/sales/held-carts` to query, post, or delete held sessions.
2. **Barcode Templates**:
   - Frontend stores sticker element layouts in `localStorage('svf_barcode_designer_templates')`.
   - Backend defines `barcode_templates` in [backend/app/models/discounts.py](file:///c:/Users/rakes/shree%20vinayaka%20furnitures/backend/app/models/discounts.py), but the frontend never invokes `/api/v1/discounts/barcode-templates`.
3. **Goods Receipt Notes & Stock Entries**:
   - Frontend `StockEntryModal.tsx` stores inward entries in `localStorage('svf_stock_entry_records')`.
   - Backend possesses `stock_entries`, `stock_entry_items`, and `stock_ledger_events` in [backend/app/models/inventory.py](file:///c:/Users/rakes/shree%20vinayaka%20furnitures/backend/app/models/inventory.py) with ready routes `POST /api/v1/inventory/stock-entries`, but the UI bypasses them.
4. **Debit & Credit Returns**:
   - Frontend `PurchaseReturnModal.tsx` and `SalesReturnModal.tsx` read history from `localStorage('rd_purchase_records')` and write debit/credit notes to `localStorage('svf_purchase_return_records')` and `localStorage('svf_sales_return_records')`.
   - Backend has dedicated tables `purchase_returns` and `sale_returns` with endpoints `POST /api/v1/returns/purchases` and `POST /api/v1/returns/sales`, yet frontend saves locally.
5. **System & Terminal Settings**:
   - Bill configurations, terminal tills, stock alerts, SMS, and email credentials reside in `localStorage`.
   - Backend has `system_settings`, `sms_settings`, and `email_settings` ready to act as the single source of truth across all showroom terminals.
